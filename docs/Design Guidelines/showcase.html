最重要的 5 条总规则
  • Token 优先：颜色、圆角、阴影、层级先走 token，不在组件里硬编码视觉值。
  • 结构先于装饰：先把层级、顺序、提示位置做对，再考虑“完整感”和装饰壳层。
  • Primitive 先于 Pattern：能直接用 shadcn 原语就先复用，业务语义再往上封装。
  • 保存主流程优先：AI 分类、AI 总结、推荐标签都属于辅助，不能压过保存本身。
  • 文档与展示页同步：命名、分层、组件目录一旦变化，docs/ 和 showcase.html 同轮更新。

Primitive / Button
docs/design/buttons.md
Primitive / Pattern

Pocket Brain 的基础按钮直接跟随 shadcn Button。页面主按钮、弹窗按钮、工具栏按钮都应建立在同一个按钮原语之上，只允许做项目变体或布局 pattern，不再维护第二套按钮 primitive。

Variants

Default — 页面主操作，每个区域只出现一次

Outline — 次要操作，与 Default 并列时用

Secondary — 中性操作，不强调

Ghost — 工具栏图标按钮、内联操作

Destructive — 删除、危险操作（不可逆）

Sizes

xs 24px — 密集列表内微操作  ·  sm 28px — 卡片/面板次要操作  ·  default 32px — 常规  ·  lg 36px — 表单提交/页面级主操作

States

基础状态遵循 shadcn Button 语义：default、hover、focus-visible、disabled 为必备状态。业务互斥、编辑器选中态等属于 pattern 层，不回写到基础按钮规范。

禁忌
  • 同一区域不要出现两个 Default 按钮
  • Destructive 只用于不可逆操作，不用于普通警告
  • 不要用 Link variant 做"取消"等界面操作，它只用于导航跳转
  • 不要在 Ghost 按钮上加 border，那是 Outline 的职责
  • 不要为工具栏或弹窗再造第二套基础按钮样式
Dialog / shadcn First
docs/design/dialog-shell.md
默认策略

Pocket Brain 的弹窗默认直接使用 shadcn Dialog 体系，不额外改造自己的壳层样式。可访问性、focus trap、overlay、header / body / footer 结构优先遵循官方原语。

推荐结构
区域 职责 当前规则
Header 标题、说明、关闭入口 直接使用 shadcn DialogHeader / DialogTitle / DialogDescription
Body 唯一可滚动内容区 表单、说明、确认文案按 shadcn 内容容器自然排布
Footer 操作区 直接使用 shadcn DialogFooter；无项目级额外壳层约束
当前结论

DialogShell 当前不再作为主规范入口，只保留为兼容封装。只有当项目后续真的形成稳定且必要的统一弹窗节奏时，才考虑重新提升为正式 Pattern。

禁忌
  • 不要在 shadcn Dialog 外面无必要再包一层项目壳层
  • 不要为了轻微视觉偏好复制一套 header / footer 结构
  • 不要让兼容层封装反过来限制 shadcn 官方结构使用
  • 只有真正形成通用业务规则时，才允许新增项目级 Dialog pattern

Primitive / Badge
docs/design/tag-chip.md
底层原语

Pocket Brain 的标签样式直接使用 shadcn Badge。如果代码里还保留 TagChip 命名，它也只视为实现层薄包装，不代表另一套设计系统组件。

  • 禁止再做一套单独的“类型徽章”，所有标签统一复用 shadcn Badge 这套样式
  • 禁止加图标，chip 只保留文字信息
  • 不要再额外做一段 tone 展示或用颜色、大小、粗细制造 Type / Source / AI / User 的视觉层级
  • 不要把项目规则写死进底层 Badge 包装里

tone 如果保留，也只作为代码层语义字段存在。设计规范层只保留一套 shadcn Badge 样式。

项目规则

无 AI 推荐时，只展示已有用户标签并允许继续新增；有 AI 推荐时，展示用户标签 + 去重后的来源/内容推荐标签。用户可在对话框里拖拽调整标签顺序。保存后，以最后留下且排好的标签集合为准；列表页和详情页按该顺序展示，如果最终没有任何标签，默认显示 其他。
